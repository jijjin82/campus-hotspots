### 실습 1
- 내가 수정한 부분: 세 장소(중앙도서관, 운동장, 채플)의 사진·설명·추천 이유를 index.html의 section 세 개에 넣고, 지도 검색어를 "경기도 부천시 원미구 역곡동 가톨릭대학교 성심교정"까지 구체적으로 적어 다른 캠퍼스(성의교정)와 혼동되지 않게 수정하였다.
- 버튼 클릭 → 내용 변경 → 지도 변경의 흐름: 버튼을 누르면 showPlace(id) 함수가 실행되어, 모든 section의 hidden 속성을 켜고 끄면서 선택한 장소만 보이게 하고, 동시에 같은 함수 안에서 지도 iframe의 src를 해당 장소의 검색어로 바꾼다.
- 휴대전화에서 확인한 결과: 버튼·설명·지도가 세로로 쌓여 잘 보였고, 가로 스크롤 없이 정상 작동한다.

### 실습 2
- 데이터 출처 URL / 내려받은 날짜: (https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=8DH8S8QY356MQXBAXKSW34715782&infSeq=1) / 2026-09-22
- 데이터 선택 이유 / 대상·기간·단위: 경기도에 거주하며 시군별 인구 규모와 외국인 거주 분포가 궁금해서 선택하였다. 대상은 경기도 30개 시·군(합계 행 제외), 단위는 명.
- 그래프 1: 질문 - 인구가 가장 많은 시는 어디인가? / 사용한 열 - 시군구, 총인구 / 그래프 형식과 선택 이유 - 막대그래프, 시군별 순서 없는 크기 비교에 적합해서 선택 / 해석 - 수원시가 1,224,223명으로 가장 많고, 2위 용인시보다 112,608명 많다. 
- 그래프 2: 질문 - 등록외국인이 가장 많은 시는 어디인가? / 사용한 열 - 시군구, 등록외국인 / 그래프 형식과 선택 이유 - 막대그래프, 그래프 1과 같은 기준으로 비교하기 위해 선택 / 해석 - 화성시가 55,380명으로 가장 많고, 이 시는 총인구 순위로는 4위이다. 
- 필터링·집계·결측치 처리: "시군구"가 "합계"인 행은 경기도 전체 합계이므로 그래프 왜곡을 막기 위해 제외하였다. 
- 두 탭 전환 방식: showPanel(id) 함수가 클릭된 버튼의 data-panel 값을 읽어 해당 section만 hidden을 false로, 나머지는 true로 바꾸고, requestAnimationFrame으로 그래프 크기를 다시 계산한다.
- 휴대전화에서 두 탭을 확인한 결과: 탭 버튼과 그래프, 해석 문장이 화면 밖으로 나가지 않고 정상적으로 보였다.
- 빈 데이터·잘못된 CSV를 넣었을 때 결과: 필요한 열(시군구, 총인구, 등록외국인)이 없으면 "CSV 형식을 확인하세요" 메시지가 표시되고, 유효한 행이 하나도 없으면 "그래프로 표시할 행이 없습니다" 메시지가 표시된다.
- Copilot 활용: 간단한 게임을 만들기 위하여 활용하였다.

- 게임 이름 / 아이디어 / 조작과 규칙: 코인 모으기 - 클릭/터치로 코인을 획득하고, 경고 표시를 누를 시에 기회가 줄어드는 게임이다.
- Copilot에게 보낸 첫 질문: "HTML Canvas와 JavaScript로 내가 상상한 작은 게임을 만든다. 클릭이나 터치로 코인을 획득하고, 장애물에 부딪히면 기회를 잃는 게임이다. 기회는 3개로 시작하고, 20초 안에 15점을 모으면 성공, 기회를 다 잃으면 실패."
- 추가 수정 요청과 개선한 점: 문제없이 게임이 만들어졌다.
- 직접 확인한 동작: 조작 / 점수 / 종료 / 재시작: 코인 클릭 시 점수가 오르고, 경고 표시 클릭 시 기회가 줄어드는 것을 확인되었다. 20초가 지나거나 15점을 모으면 성공/실패 메시지가 나타나고, 재시작 버튼을 누르면 처음 상태로 돌아가는 것을 확인되었다.

## 5주차 · 나만의 취향 밸런스 게임

- 게임 주소: https://jijjin82.github.io/campus-hotspots/week5/
- 게임 이름과 소개: 우리 캠퍼스 생활 궁합은? — 공강, 점심, 시험 기간 등 여섯 번의 선택으로 캠퍼스 생활 스타일을 알아보고, 같은 기기에서 동기와 번갈아 도전해 비교하는 게임
- 게임의 대상과 주제를 선택한 이유: 3·4주차에 성심교정 명소(중앙도서관·운동장·채플) 사이트를 만들었기 때문에, 같은 캠퍼스를 쓰는 동기들이 학교생활을 어떻게 보내는지 비교해 보면 대화거리가 될 것 같아 선택함
- 기본 예제에 없는 질문 최소 4개: 오늘 점심은? / 비 오는 날 수업 사이 쉬는 시간 / 시험 기간 공부 스타일 / 동아리를 하나 고른다면?
- 직접 만든 결과 이름·설명과 선택의 연결: 모든 질문에서 첫 번째 선택지는 조용하고 익숙한 쪽, 두 번째는 활동적이고 새로운 쪽으로 방향을 맞춤. 첫 번째 쪽을 많이 고르면 "조용한 도서관파", 두 번째 쪽을 많이 고르면 "활기찬 운동장파", 반반이면 "여유로운 채플파"로 3주차의 세 장소와 연결
- 나만의 표현 한 가지와 구현한 위치: 결과별 추천 공강 코스. RESULTS의 각 결과에 course 속성을 추가하고, 결과 카드의 `#result-course` 요소에 showResult() 함수에서 textContent로 표시
- 결과 분류 규칙과 동점 처리: 첫 번째 선택 0점, 두 번째 선택 1점. 6문항 합계가 3점 미만이면 도서관파, 3점 초과면 운동장파, 정확히 3점(절반)이면 채플파. 동점이 나올 수 있도록 문항 수를 짝수(6개)로 정함

### 저장 설계
- sessionStorage에 저장한 값과 이유: `week5.balance.draft` — 진행 중인 참여 ID, 버전, 별명, 답변, 현재 문항. 같은 탭에서 새로고침하거나 이동해도 이어서 답할 수 있어야 하지만, 탭을 닫으면 새 판으로 시작하는 것이 자연스럽기 때문
- localStorage에 저장한 값과 이유: `week5.balance.history` — 완료 기록 배열(참여 ID, 버전, 별명, 답변, 결과 유형, 완료 시각), 최근 20개. 다음 친구가 도전한 뒤 비교해야 하고 브라우저를 닫아도 남아야 하기 때문
- 내 데이터 조회·개별 삭제·전체 삭제 동작: "내 저장 데이터 보기"는 누른 시점의 저장소를 다시 읽어 표시. 기록 하나 삭제는 filter()로 해당 ID를 뺀 배열을 다시 저장. 전체 삭제는 clear()를 쓰지 않고 이 게임의 두 키만 removeItem으로 지우고, 메모리의 draft·history와 화면도 함께 초기화
